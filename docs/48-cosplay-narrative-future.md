# 48. 未来方向设想：AI Cosplay 交互式叙事（游戏化外壳）

日期：2026-08-02

状态：**想法记录；未立项，供未来评估**

来源：作者在一次迭代讨论中提出的设想——"确定一个世界观，让大模型自己做主角，以写小说的形式推动剧情发展，像玩游戏一样"。本文把它结构化记录为未来方向，不承诺实施。

## 想法概述

与现有产品（"作者最终决定的长篇小说生产系统"）相反，这是一个体验型产品：**体验过程本身就是产品**。

- 确定一个世界观（复用现有 `start --world --conflict` 式设定）；
- 大模型扮演主角，有私欲、有误判、会自作主张；
- 用户通过世界反馈干预（事件、代价、奖励、剧情转向）；
- 每一轮以"小说体叙事"推进，像文字冒险游戏；
- 可选：游戏结束后，全部轮次叙事拼接即为一部小说（过程是游戏，小说是副产品）。

已有成熟先例：AI Dungeon、AI 跑团等。本设想的独特点在于**复用本项目积累的叙事基础设施**，把"叙事一致性控制面"变成游戏的引擎。

## 核心设计问题：主角控制权归属

| 模式 | 谁行动 | 用户角色 | 叙事动力 |
|---|---|---|---|
| A. LLM 全权主角 | 大模型自主决定主角行为 | 旁观者 | 容易线性化，缺乏互动 |
| B. 用户主控 + LLM 演世界 | 用户下达主角指令 | 主角本人 | 经典文字冒险，"大模型做主角"消失 |
| C. LLM 演主角 + 用户演世界/命运 | 主角有欲望、会反抗干预 | 神/金手指/同伴 | **最富戏剧性，两个智能体互相博弈** |

C 是推荐方向：用户给代价与奖励，主角带着私人欲望回应甚至反抗，形成"作者 vs 角色"的张力——这正是现有"人物选择与私人代价"机制的交互化。

## 可直接复用的现有资产

| 现有机制 | 在交互叙事中的用途 |
|---|---|
| Scene Package 的私人欲望 / 关系摩擦 / 感知偏差 | 主角"为什么会这么做"的决策引擎 |
| 硬锚合同 + 信息账本 / Canon 候选与晋升 | 世界观一致性；LLM 玩长了会忘设定，这是所有 AI 冒险游戏的死穴 |
| 因果链 / 章际交接 / 伏笔管理 | 长程剧情不崩 |
| 声音指纹（Voice Bible） | 主角说话"像一个人"而非通用 AI |
| 审稿 / 一致性校验（Blind Reader 等） | "剧情逻辑警察"：自动检查主角行为是否违背已建立的世界观 |
| 每书本地 Git checkpoint | 存档/读档，剧情走崩可回滚 |
| `authorize-revision` 类作者决策机制 | 关键剧情分叉由用户显式确认 |

## MVP 设想（若立项）

1. **单会话循环**：世界观卡 → LLM 写第一段（主角视角叙事）→ 用户输入干预/环境事件 → LLM 以主角身份回应并推进 → 循环；
2. **两份持久状态**：`世界账本.md`（已确立事实，只追加）＋ `主角档案.md`（欲望、恐惧、欠下的债）；每轮由确定性控制面自动追加新事实，防遗忘；
3. **一轮一次代价**：强制每轮主角行动有可感知后果（沿用"行动后果与停止点"规则）；
4. **存档/读档**：每轮 checkpoint，可回滚；
5. **顺带产出原稿**：记录每一轮叙事，游戏结束即一部可接回现有生产流程的小说稿。

## 风险与难点

- **剧情失控**：LLM 主角会自发推向未预期方向。需要"世界硬规则护栏"（不可违反的世界观约束）与可回滚存档，而非试图让它听话；
- **结束条件**：游戏要能收敛（主线完成 / 目标达成 / 玩家放弃），并明确存档语义；
- **哲学反转**：现有系统"人是作者、LLM 是工具"；本产品"体验是产品"。若同时保留成品价值，必须让游戏过程可回放为小说，而不是只留下聊天记录；
- **一致性与记忆成本**：长程会话的上下文膨胀；账本机制可缓解，但仍需预算约束（可复用 45 号 P0/P1/P2 上下文预算思路）。

## 结论

不切实际之处只在于它改变了产品形态，不改变技术可行性。本项目叙事引擎的"游戏化外壳"是合理的未来方向之一；若启动，建议从 CLI 原型开始（世界观卡 + 双账本 + 每轮代价 + checkpoint），一晚可跑通，再决定是否加 UI。

实施优先级：**低于** 47 号文档中列出的下一轮迭代意见（双审并行化等核心工作流优化）。
