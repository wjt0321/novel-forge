# 45. 小说生产工作流迭代提案与阶段 1--5 实施记录

日期：2026-07-31

状态：**阶段 1--5 已实施；默认策略由作者于 2026-07-31 确认**

范围：本文评估并记录 `S-Black Novel Forge` 默认 `lean_native` 工作流的本轮迭代。阶段 1 只增加观测；阶段 2--5 在保留 5000 CJK、核心双审、至多一次文学 Patch、正式稿隔离和作者最终决定权的前提下完成路由收缩。

## 目标与不可退让项

本次迭代不是把流程“放松”，而是在保持成稿质量和可恢复性的前提下，解决四个已确认问题：

- AI 文风高频机械特征难以彻底压制，且切换 Writer 模型时风格断裂。
- 强推理 Lead 容易被状态、会话和恢复语义吸走；弱 Lead 容易绕过独立角色，自己包办写作与审稿。
- 单章重复全量阅读和重复修订，消耗过多 token 与时长配额。
- 流程复杂度可能反过来吞噬创作本身。

以下约束 **MUST 保留**：

- 正文在通过质量门前不得进入正式 `chapters/`。
- Writer、Blind Reader、Chapter Editor 的职责分离，以及 Blind Reader 与 Editor 的双审价值必须保留。
- 作者是唯一最终批准者；`ready` 不等于作者批准或可发布。
- canon 新事实仍先进入 candidate，再经显式 promotion；模型分析不得自动成为权威事实。
- 正文中的破折号、省略号、否定翻转机械句、句式均匀化及既有高频 AI 味反模式，继续作为硬质量标准处理。
- 每书本地恢复能力、正式稿隔离和必要的控制面完整性不得被取消。

## 重新确认：现有硬文学规则是必要资产

“禁破折号、禁省略号、禁‘不是 X，而是 Y’、控制句长方差、检查高频反模式、双审识别模型味”不是装饰性规则，也不是可以用“少一点约束”取代的偏好。

它们来自重复观察到的高频模型污染：一旦没有硬闸，某些模型会把同一种句法、断句和转折方式扩散到整章甚至整书。问题不在于单个标点或单个句式偶尔出现，而在于它们成为文本的统计性习惯，覆盖人物、场景和节奏本应有的差异。

因此本提案的原则是：

> **减少 Writer 必须理解的流程负担，不减少对成稿的硬质量约束。**

具体来说：硬规则继续由本地 deterministic lint 和 gate 执行；Writer 只接收极短、可执行的提醒；Blind Reader 与 Chapter Editor 继续负责机器规则无法可靠判断的“读感”和“文学后果”。

## 现状诊断

### 文风问题：规则挡住表征，仍未稳定塑造声音

现有 lint 能有效拦截高频表征，但文风稳定性还受三个因素影响：

- Writer 每章接收的规划、连续性、规则和修订信息较多，模型会趋向安全解释和均匀表达。
- 同一本书切换 Writer 模型时，叙事距离、句子呼吸、对白密度和信息释放习惯会自然变化；这不是靠禁令能完全抹平的。
- 正面风格证据（经过作者认可的正文片段、其叙事功能说明）尚未成为每书、每卷稳定且轻量的 Writer 输入。

### 调度问题：模型被暴露给了不该由模型承担的复杂性

当前 v5.4 已经把哈希、Git、Guardian、状态推进等归入 Python 控制面，方向正确。但 Lead 仍需理解“下一动作—独立角色—等待宿主终态—complete-role”的编排语义。

- 强推理模型会把看见的状态、失败和恢复语义视为待解决对象，进而耗费大量推理在协议闭环上。
- 弱模型会把多角色要求视为可选提示，选择自己直接写正文、自己审稿的最短路径。
- 仅以自然语言规则要求 Lead 使用独立角色，无法提供真正的隔离保证。

### 成本问题：同一章被多次完整阅读

双审本身不是浪费；它是质量保险。主要成本来自不分风险地重复全量上下文和全章修订：Writer 读大包上下文、两名审稿人读全文、修订 Writer 又读全文和完整材料、复审再次读全文。

而真实问题常常是局部的：一处解释性补丁、重复动作、AI 腔、物件状态不连续，未必需要让 Writer 整章回炉。

### 复杂度问题：系统已经有“正文优先”的原则，但尚未完全做到“默认最短路径”

`lean_native` 是正确收缩；下一步不应重新加角色或加表，而应把复杂性进一步收进 Python，并让日常生产按风险选择最小充分流程。

## 可吸收的外部启发

外部工具的优势不在于它的长 Prompt 或“模型分析自动写回数据库”；这两点不应照搬。可吸收的是以下工程原则：

- 后端程序直接编排有限 AI 调用，模型不承担状态机解释责任。
- 写作上下文分为 P0（必须）、P1（重要）和 P2（可裁剪参考），按预算装配。
- 风格是独立、可版本化的资产，而不是散落在许多提示与审稿意见中的规则。
- 局部重写可只带目标片段和前后文，避免整章再生成。
- 每次模型调用都记录输入、输出、时长、重试和 token，用数据检验流程是否值得。
- 对用户展示简单任务状态，不暴露内部实现细节。

以下做法 **NEVER 吸收**：

- 将模型的章节分析自动升级为角色状态、关系、伏笔或 canon 事实。
- 要求一次模型调用输出臃肿 JSON，涵盖所有人物、组织、评分、伏笔和世界状态。
- 用目标字数或结构表单压过场景完成度。
- 因为追求成本而取消双审或让同一 Agent 冒充独立审稿角色。

## 目标工作流：质量分层，不是质量降级

建议把默认 `lean_native` 演化为一个由 Python 决策的“质量路由器”。作者看到的仍然是简洁流程；硬门、双审与隔离均保留。

```text
准备最小 Writer 包
  → Writer 初稿（唯一暂存正文）
  → 本地硬门：AI 味 / 格式 / 连续性可验证项
  → Python 依据章节风险选择审稿深度
      ├─ 标准：Blind Reader + Chapter Editor
      └─ 高风险：Blind Reader + Chapter Editor + 必要的额外人工决策点
  → 合并 MUST
      ├─ 局部问题：局部 Patch
      ├─ 结构问题：章节级 Patch
      └─ 第二轮仍有 MUST：作者决定
  → 双审通过
  → Python 晋升、记录恢复点、ready
```

“标准”仍然是双审。所谓分层不是将低风险章改为单审，而是改变：

- Writer 输入量；
- 审稿输入量；
- 修订的粒度；
- 是否增加额外审稿或卷段审查；
- 是否需要作者提前确认。

## 提案 A：Writer 采用最小上下文预算

### A1. 三层输入

Python 编译 Writer 包，而不是把资料目录、长规则或整个历史交给 Writer。

| 层 | 内容 | 建议预算 | 原则 |
|---|---|---:|---|
| P0 必须 | 本章场景压力、人物选择与代价、硬锚、章末目标、上章结尾 | ≤1,500 CJK | 缺失即无法写 |
| P1 重要 | 人物状态、直接 canon、最多两条伏笔、关系摩擦与感知偏差 | ≤850 CJK | 只保留当章会影响选择的事实 |
| P2 风格 | 书级声音基础与卷级覆盖的功能摘要 | ≤450 CJK | 定义叙事功能，不复制句法外壳 |

上章承接应默认是“结尾片段 + 可靠摘要”，不是整章全文；只有 Chapter Editor 或作者明确标记为高连续性风险时，才扩大到更长上下文。

### A2. 风格资产版本化

每书增加不可自动改写的 `voice-bible` 投影，建议按“书级基础 + 卷级覆盖”维护：

- 叙事距离；
- 信息释放顺序；
- 对白和沉默的使用倾向；
- 场景如何承载人物选择与私人代价；
- 作者批准的正例片段及其功能说明；
- Writer 模型基线与切换记录。

硬禁令仍然由 lint 执行，不依赖风格包。风格包只解决“应该朝哪里写”，不将范文的词汇、句长、意象机械复制为新模板。

### A3. Writer 模型连续性

- 同一书、同一卷 **SHOULD 固定主 Writer 模型**。
- Blind Reader 与 Chapter Editor 可以使用不同模型以获得异质判断。
- 必须更换 Writer 模型时，先进行“非正式风格校准”：用同一短场景写一小段，作者确认其可用后才写正式章。
- 模型切换记录进入风格资产，但不得让模型自己决定或自动覆盖既有声音。

## 提案 B：从“Lead 编排”迁移到“Python 直接角色调度”

### B1. 角色隔离改为能力，不是提示词要求

理想状态下，Python/宿主适配层直接创建三个具备受限输入和唯一输出路径的角色任务：

- Writer：只获得 Writer 包，只能写暂存正文；
- Blind Reader：只获得正文，只能写盲审结果；
- Chapter Editor：获得正文、最小场景约束和盲审结论，只能写编辑结论。

Lead 不再是日常生产中的编排主体；它最多承担“启动一次生产 / 展示结果 / 把作者决定交给 Python”的薄交互层。

### B2. 对宿主能力做显式分级

不应假设每个模型、每个 ACP 或每个宿主都能可靠创建并等待独立子代理。建议引入能力档，而不是用自然语言赌模型自觉：

| 档位 | 条件 | 行为 |
|---|---|---|
| Native-isolated | 宿主可由程序创建、等待、绑定独立角色 | 正式双审生产默认档 |
| Managed-relay | 宿主可执行受控单角色调用，但无法由 Lead 管理子代理 | Python/适配器直接逐个调用角色，Lead 不介入 |
| Exploration | 无独立角色能力 | 只能做探索稿，永不进入正式 `ready` |

弱模型不再有机会“自己决定是否创建子代理”；强模型也不再看到足以让它沉迷的恢复协议。

### B3. 用户可见状态收缩

日常界面/输出只展示：

```text
待写 → 写作中 → 硬检查 → 双审中 → 待局部修订 → 待作者决定 → 已归档
```

hash、capsule、Guardian、session、Git、重试计数与 runtime 只进入日志和诊断入口；不出现在 Writer、Reader、Editor 或 Lead 的日常上下文中。

## 提案 C：保留双审，改造修订成本

### C1. 将 MUST 分为局部与结构两类

Blind Reader 和 Chapter Editor 仍须一次列全 MUST；但每条 MUST 增加程序可读字段：

- `scope=local`：能限定到连续段落，不改变本章核心事件；
- `scope=structural`：涉及人物选择、因果、章节节奏、硬锚或钩子；
- `scope=blocking`：硬规则、事实矛盾、知识越界、正式稿污染风险。

该分类由审稿角色建议，最终由 Python 的保守规则和作者决定共同约束。审稿人仍给自然语言理由，不能只输出标签。

### C2. 局部 Patch 成为一等路径

当全部开放 MUST 都是 `local` 时：

- Writer 只获得目标片段、前后各一小段、不可改变事实的锚点和修订意图；
- Writer 只输出替换片段；
- Python 做精确替换，重新运行全章本地硬门；
- Blind Reader 与 Chapter Editor 仍复审**完整新正文**，从而不牺牲双审。

收益来自降低 Writer 修订调用的输入/输出，而非跳过复审。

### C3. 结构性 Patch 保持章节级

以下情况仍必须使用章节级修订：

- 主动选择或私人代价不成立；
- 硬锚漂移；
- 关键因果、物理状态、人物知识来源矛盾；
- 钩子、场景主冲突或章节结构失效；
- 多个局部问题共同指向同一叙事结构缺陷。

第二版仍有 MUST 时继续停在作者决定处。此规则不放松。

## 提案 D：双审从“重复审读”升级为“互补审读”

双审不取消，但应确保两个角色不是用不同措辞重复同一份检查表。

### Blind Reader 的唯一职责

- 人物是否不可替换；
- 是否愿意读下一章；
- 情绪余波是否真实；
- 文本是否有明显的模型腔、规划答卷感或修补接缝；
- MUST 只限于“不修将明显损害阅读体验”的问题。

它只读正文，不读大纲、canon、规则、前章或技术材料，以保证盲性。

### Chapter Editor 的唯一职责

- 人物选择、私人代价、因果、硬锚、知识来源；
- 物件/身体/空间/时间连续性；
- 章内信息释放和章末钩子是否与场景契约一致；
- 识别 Blind Reader 无法判断的事实与结构问题。

它读取正文 + 最小 scene contract + 必要 canon 差异；不读大包项目记忆。

### 审稿输出继续短小

不引入外部工具式“钩子、伏笔、人物关系、组织状态、评分、比例、建议”的超长 JSON。每个审稿角色仍只输出 verdict、完整 MUST、简短原因和可验证引文；质量判断不被格式表单吞噬。

## 提案 E：硬规则前移到程序，文学判断留给人和模型

硬规则的价值被确认，应当增强其执行确定性，而非把更多文字规则加进 Writer prompt。

### 适合本地 deterministic gate 的项目

- 禁止破折号、省略号、否定翻转机械句；
- 句长方差、连续同构句、重复段首等可检测模式；
- 工作流/控制面泄漏；
- CJK 字数、文件路径、章节序号与正式稿污染；
- 角色、物件、时间等已有结构化事实的直接冲突（仅在有确定事实时）。

### 必须保留给双审的项目

- 文风是否“像人”；
- 人物是否有不可替代的欲望与羞耻；
- 留白是否有效而非缺漏；
- 对白是否有权力关系，而非整齐问答；
- 修订是否形成解释性接缝；
- 钩子是否真实牵引读者。

原则：**规则不减少，但将规则解释从 Writer 上下文移到程序运行结果。** Writer 只在失败后接收命中位置和一次性修订任务。

## 提案 F：为每章建立成本账本与预算熔断

每次模型调用记录：

- 角色、模型、调用目的；
- 输入/输出 token；
- 时长、重试、是否生成了实际正文变化；
- 调用前后正文摘要；
- 该调用是否导致晋升、修订或作者决策。

每章输出一个内部成本摘要，供作者查看但不强迫 Writer 阅读：

| 指标 | 用途 |
|---|---|
| Writer 初稿 token | 判断主生成成本 |
| 双审 token | 判断质量保险成本 |
| 局部/结构修订 token | 判断规则与审稿是否造成返工 |
| 重试 token | 定位宿主/运输浪费 |
| 控制面调用数 | 检查系统是否重新暴露给模型 |

建议设置两类预算：

- **软预算**：达到后不再自动触发 optional 深度检查，保留核心双审与硬门；
- **硬预算**：达到后停止自动追加调用，保存暂存稿和完整上下文，进入“待作者决定”。

预算熔断不是把质量问题放过，而是防止系统在没有新增信息时继续燃烧额度。

## 建议实施顺序

以下按“收益高、破坏面小、可独立验收”排序。每个阶段完成前不进入下一阶段。

### 阶段 1：只观测，不改变产出

- 加入逐调用 token、时长、重试与正文变化记录。
- 汇总最近若干章的“初稿 / 双审 / 修订 / 复审”成本比例。
- 抽样标记 MUST 的 `local` 与 `structural` 比例，但不改变现有修订路径。

验收：能用真实数据回答“token 花在哪里、哪类问题最常导致整章回炉”。

#### 阶段 1 实施结果（2026-07-31）

本阶段已经落地，且观测结果不参与路由或质量判断：

- 每个 Native action 完成或进入技术重试时，在
  `.local-guardian/<slug>/workflow-observations/chNN/<action-id>.json` 写入一次性本地观测。
- 记录角色、模型、调用目的、输入/输出/缓存/总 token、请求数、耗时来源、技术重试序号、
  修订轮次、调用前后正文 SHA-256 与 CJK 摘要、正文是否实际变化，以及调用是否导致修订、
  晋升或作者决策。宿主没有提供的遥测保持 `null`；Relay 只补充明确标记为
  `relay_wall_clock` 的墙钟耗时。
- Blind Reader 与 Chapter Editor 的 MUST 可附带 `scope=local|structural|blocking`；旧的字符串
  MUST 自动归为 `unclassified`。该字段只做比例抽样，Python 仍执行现行章节级集中 Patch。
- 作者可运行
  `python tools/novel-workflow.py --root <绝对根目录> cost-summary <slug> [--chapter N]`
  查看简明摘要；宿主程序集成可加 `--json`。
- 可选 `complete-role --telemetry-file <json>` 只供宿主提供实际调用指标。遥测文件缺失、损坏或
  字段无效不会使合规正文或已接受审稿重做，只会留下未知值或 warning。
- 观测写入后，Relay 会刷新当前待执行动作的完整性基线，避免 Python 自己新增的本地记录被
  误判为创作角色越权修改。

阶段 1 当时没有改变路由；下列阶段现已按顺序实施，观测记录继续保持不可作为作者批准或发布资格证据。

### 阶段 2：最小 Writer 包与声音资产

- 为当前书增加书级/卷级 `voice-bible` 投影，不自动迁移历史内容。
- Python 编译 P0/P1/P2 Writer 包；保留原完整包作为对照开关。
- 固定每卷 Writer 模型；建立模型切换的非正式校准流程。

验收：同模型下 Writer 输入显著收缩，硬门通过率、双审通过率和作者主观读感不下降。

### 阶段 3：局部 Patch 路径

- 扩展审稿结果，使其可建议 `local` / `structural` 范围。
- 仅在全部 MUST 为局部且可定位时启用局部 patch。
- 局部 patch 后仍全章硬检、仍双审复核。

验收：局部问题不再触发整章 Writer 回炉；双审结论与正式晋升不被削弱。

### 阶段 4：控制面去 Lead 化

- 把独立角色创建、等待、结果导入收进 Python/宿主适配器。
- Lead 日常只发起任务、呈现简化状态、转交作者决定。
- 为 Native-isolated / Managed-relay / Exploration 明确提供能力检测和停止行为。

验收：强模型不会读到状态机细节；弱模型无法通过自己代写/代审获得正式 ready。

### 阶段 5：按风险增加质量，不按惯性增加调用

- 保持每章双审为标准线。
- 对卷首、卷末、重大转折、角色生死、核心设定揭示等高风险章，增加作者确认或专项审查，而不是给所有普通章无限加角色。
- 对连续多章稳定通过的书，使用成本账本审视可选检查，而不动核心双审。

验收：质量投入集中在真正会伤害整书的章节，而非平均摊薄到每一次调用。

## 明确不做的事

- 不取消破折号、省略号、否定翻转、句长方差和既有模型味硬标准。
- 不取消 Blind Reader 与 Chapter Editor 双审。
- 不允许同一 Agent 以不同身份替代独立 Writer/Reader/Editor。
- 不让 AI 分析自动写成 canon、角色关系、人物心理或伏笔真相。
- 不把 `ready` 改成作者批准。
- 不为降低 token 而默认跳过复审。
- 不重新把完整哈希、会话、Guardian、Git、runtime 表单暴露给日常创作角色。

## 成功标准

迭代成功不是“规则变少”或“流程看起来更先进”，而是同时满足：

- 高概率 AI 污染仍被硬门拦住，且双审认为读感没有下降；
- 同一卷 Writer 文风更稳定，换模型时有受控校准而非无声漂移；
- 强模型不再消耗大量推理处理状态机；弱模型无法越过独立角色边界；
- 局部问题优先局部修订，单章平均 token 和耗时有可量化下降；
- 有效暂存正文、正式稿隔离、作者决定权、双审和回滚能力全部保留。


## 阶段 2--5 实施结果（2026-07-31）

### 阶段 2：最小 Writer 包与声音资产

- Guardian 在 Lean Writer capsule 中生成受保护的 `writer-context.md`。默认 `minimal` 模式由 Python 编译 P0/P1/P2：上限分别为 1500/850/450 CJK，总预算不超过 2800 CJK；`full` 保留旧 handoff 作为对照开关。
- P0 优先当前场景压力、人物选择与私人代价、硬锚点、章末目标和上一章结尾；P1 带直接人物/Canon、最多两个承诺，以及原 Scene Package 中的私人欲望、关系摩擦和感知偏差；P2 只带书级声音基础和卷级覆盖。编辑专用替代解释不进入 Writer 核心。
- 当前卷按需创建 `memory/voice-bible-vNN.md`，记录叙事距离、信息释放、对白/沉默、选择与私人代价、认可范例及 Writer 模型切换。模型基线存于本地控制面；不同模型未经 `approve-writer-model` 校准不能无声进入该卷。

### 阶段 3：局部 Patch

- 审稿 MUST 的 `scope=local|structural|blocking` 已进入真实路由。只有全部开放 MUST 都是 `local`，引句可在唯一连续段落中精确定位时，才签发 `local-patch`。
- 局部 Writer 只收到目标段、小范围前后文、修订意图和不可变锚点，只返回 `target/replacement`；Python 校验正文 SHA、目标集合和唯一匹配后执行精确替换。
- 替换后对完整暂存正文重新运行硬检查并重新签发完整 Blind Reader + Chapter Editor 双审。结构性、阻断性、未分类或不可唯一定位的问题仍走原章节级集中 Patch；第二版仍有 MUST 仍进入作者决定。

### 阶段 4：能力档与薄控制面

- 动作显式声明 `dispatcher=python_or_host_adapter`、`lead_involved=false`、能力档与 `formal_ready_allowed`。日常交接卡只显示角色输入/输出和完成命令。
- `native-isolated` 与 `managed-relay` 可执行正式流程；`exploration` 可以保留暂存正文和双审结果，但 Python 在晋升前强制停止，永远不能获得 formal `ready`。
- `capability <slug>` 可展示当前能力档；动作同时带 `display_state`，统一为待写、写作中、硬检查、双审中、待局部修订、待作者决定、已归档。

### 阶段 5：高风险与预算断路

- `volume_start`、`volume_end`、`major_turn`、`character_death`、`core_reveal` 在完整双审通过后、正式晋升前进入作者确认；`approve-high-risk` 才允许 Python 晋升。普通章仍保持标准双审，不增加无限角色。
- 可选软/硬 token 预算由 `start` 参数保存。软预算只关闭 optional 深度检查；硬预算不取消已经要求的首轮双审，只在准备追加 Patch/复审调用时保存正文、MUST 和双审结果并进入作者决定。`continue-budget` 可由作者明确授权继续一次。
- 所有新状态继续写明 `author_approval=False`、`publication_eligibility=False`；高风险确认和预算继续授权也不等于发布批准。

## 2026-07-31 文学核心压缩实施结果

本轮不增加角色、状态、模型调用或规划文件，只压缩现有 Writer、双审和本地观测：

1. **Writer 核心**：默认上下文从 4000 CJK 上限压到 2800 CJK；Scene Package 在原文件内加入私人欲望、关系摩擦、感知偏差。Writer 只读 `writer-context.md`，写完后在同一次调用中静默删去重复解释和最机械的一处重复反应，不输出检查过程。
2. **零调用纹理提示**：纯 Python 统计段首重复、延迟反应套语、解释回声、句长方差和重复短语。结果只进入 `narrative_report`、Lean Editor 的至多 160 字提示及成本摘要，`blocking=False`、`routing_affected=False`；它不判断作者身份，也不认证文学价值。
3. **双审阈值**：Blind Reader 的 `uncertain` 默认不触发修订；`synthetic` 必须引用正文证据，并返回 `needs_revision` 与恰好一条 `structural` MUST。Chapter Editor 独立检查逻辑，只在问题分布广、值得唯一一次修订时确认。
4. **调用不扩张**：默认角色仍只有 Writer、Blind Reader、Chapter Editor；章节状态不变，`MAX_AUTOMATIC_GENERATIONS=2`，即初稿加至多一次文学修订。局部 replacement 和章节级 Patch 均沿用现有路由。
5. **省 token**：先减少 Writer 输入，再用确定性提示帮助现有 Editor 聚焦；不增设“去味 Agent”、评分矩阵、全文第三审或自动循环。
